**Live Demo:** [darkmoon.dev](https://darkmoon.dev)

## ✨ Features

- `[shipped]` **Combat Gameplay with AI Bots** — Full deathmatch and CTF modes with bot LOS checks, weapon reload system (including timing-based precision snap mechanic), angular spread, bot jumping, tracer beams, hit direction indicators, score tension alerts, and ShotgunVFX cone particle effects.
- `[shipped]` **Shooting Gallery Mode** — Standalone target-practice mode with crosshair and bot tracer improvements.
- `[shipped]` **Mouse-Aimed Firing & Player Reticle** — Shots fire from the viewport centre where the reticle is fixed; velocity-based smooth movement with camera-relative A/D strafing.
- `[shipped]` **Pluggable Game Mode Architecture** — `GameModeHandler` interface decouples mode logic; `TagMode` (with health/damage support), `DeathmatchMode`, and `CTFMode` ship as reference implementations.
- `[shipped]` **Modular UI Architecture** — `GameUI` and `Solo.tsx` fully componentized: 15 HUD sub-components, 3 new hooks (`useGameStart`, `useBotPositionHandlers`, `useDebugModes`), and a dedicated `useGameUIState.ts` for all event-driven state.
- `[shipped]` **WebSocket Server Foundation** — Socket.io and server validation are in place for future live modes.
- `[in-progress]` **Multiplayer 3D Gameplay** — Multiplayer foundations exist, but the deployed experience is still solo-first.
- `[in-progress]` **Mobile Support** — Responsive layout and touch controls exist, but device validation is still open.
- `[shipped]` **Modern Tooling** — Vite, Vitest (659 tests), ESLint, Prettier, TypeScript, and CI are wired into the repo.

## Quick Start

```bash
# Dev server (hot reload via Vite)
docker compose -f config/docker-compose.yml up solo
```

Visit `http://localhost:4444`. **Solo mode is the only live experience; multiplayer is not yet available.**

## Development

All checks run via Docker — no local Node.js required.

```bash
# Run all tests (659 tests, Vitest)
docker compose -f config/docker-compose.yml --project-name darkmoon --profile test run --rm test

# Lint
npm run lint:docker

# Production build
docker build --target runner -t darkmoon-prod .
docker run --rm -p 4444:4444 darkmoon-prod
```

### End-to-end tests (Playwright)

E2E specs live in `e2e/` and run against the dev server (`solo` service, port 4444). The dev-only test probe (`window.__darkmoonTest.getSnapshot()`, see `src/lib/testProbe.ts`) is installed only when `import.meta.env.DEV` is true, so it is not present in production builds.

Run one scenario locally in Docker:

```bash
# 1. Start the dev server (same as CI)
docker compose -f config/docker-compose.yml --profile test up -d solo

# 2. Run a single spec inside the solo container (Chromium is preinstalled in the dev image)
docker compose -f config/docker-compose.yml exec solo \
  npx playwright test --config config/playwright.config.ts e2e/smoke.spec.ts

# 3. Stop it
docker compose -f config/docker-compose.yml --profile test down
```

Swap `e2e/smoke.spec.ts` for `e2e/movement.spec.ts` (or any other spec file) to run a different scenario. CI runs every spec in `e2e/` (directory glob), so a new `e2e/*.spec.ts` file is picked up automatically.

**Where the output goes.** The `solo` container mounts the repo at `/app`, so output lands in the host checkout:

- `test-results/e2e-report.json`: the Playwright JSON report (written by the `json` reporter in `config/playwright.config.ts`).
- `test-results/<test-name>/`: per-test folders with `trace.zip` (retained on failure), video (on failure) and screenshot (on failure).
- `playwright-report/`: HTML report folder (not generated by the current config; ignored if absent).

**Reading the JSON report.** Start with `stats` (`expected`, `unexpected`, `flaky`, `skipped`); any non-zero `unexpected` or `flaky` means a failure. Then walk `suites[].specs[]`: each spec has `title`, `ok`, and `tests[].results[]`, where `status` is `passed`, `failed`, `timedOut`, or `skipped` and `errors[].message` holds the failure text. To inspect a failure step by step, open its trace:

```bash
npx playwright show-trace test-results/<test-name>/trace.zip
```

**In CI**, the `e2e` job uploads `test-results/` and `playwright-report/` as the `darkmoon-e2e-diagnostics` artifact on every run (`if: always()`, kept 14 days). Download it from the workflow run's Artifacts section.

**Git hooks** are managed by husky and run Docker automatically:

- **pre-commit**: runs lint-staged via Docker (lint changed files)
- **pre-push**: runs full test suite in Docker

Install hooks after cloning:

```bash
npm install   # triggers husky install via `prepare` script
```

**pre-commit** (optional, adds basic file hygiene on top of husky):

```bash
pip install pre-commit && pre-commit install
```
